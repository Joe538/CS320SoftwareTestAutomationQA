How can I ensure that my code, program, or software is functional and secure?
Ensuring that my code/program is secure requires that I test my software as much as possible. It's impossible to exhaust every possible scenario but testing critical points with as many tests you can run is paramount to software securtiy and functionality. You can perform various black box testing techniques when focusing on inputs and out puts. White boxing techniques can be used when focusing on paths, conditions, and loops. Theres also other approaches such as manual testing, test driven devlopment and automated testing. Automated testing is a must have for any modern application. It allows quality engineers to focus on connection points and integrations of the application while automating most logic testing points at low level code. So, I think the best way to ensure code is functional and secure is to use CI/CD for automating low level testing, perform black box testing on big picture code, and perform white box testing on big picture code. Lastly, I would say to test early and as often as possible. Safety critical systems will alot more time than non-safety critical so test efficiently and effectively.

How do I interpret user needs and incorporate them into a program?
The best way to interpret user needs is to look at feedback, observe user behavior, and look at user stories. These are great ways to take user behavior and needs/wants, then build an application or update that will reflect those needs. It's important to realize that not all needs are feasible but at least worth the time to investigate.

How do I approach designing software?
With designing any modern software that is at least moderately complex, an iterative approach is the most efficient way. With so many uncertainties in the project it's important to analyze the problem you're trying to solve, then start by building and testing a starting solution. With each iteration that solution will become more effective at solving the problem while evoling into a more concrete real solution. It's important to note how crucial it is to start testing right away. The earlier a team test and catch errors, the cheaper the solution. It can help catch fundemental issues before they're used elsewhere which makes fixing the problem so much easier.
